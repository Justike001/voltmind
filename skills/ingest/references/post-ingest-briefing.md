# Post-ingest briefing handoff

Read this reference for every user-visible ingest request, including specialized
meeting/media/idea ingestion and requests producing no actions. Read
`skills/briefing/SKILL.md` completely: it owns report collection, prioritization,
citations, and layout. This reference only owns the handoff.

## Completion order

1. Finish evidence preservation, canonical updates, validation, synchronization
   attempts, and tracking/receipt checks under the ingest core workflow.
2. Show a concise ingest result, identifying pending/failed work. Deliver today's
   briefing before the first action scheduling interview. Missing remote access
   must not hide durable local work; disclose partial coverage and stale data.
3. Continue `skills/schedule-actions/SKILL.md` for durable local action candidates,
   preserving its raw-evidence-first handoff and consent requirements. Report
   recommendations are not execution consent.

Produce the report even with zero actions, duplicate evidence, or no changes.
A report failure does not undo durable ingest or mark incomplete ingest complete:
return the useful subset with limitations, then continue action handling.
High-impact clarification gates still apply before dependent canonical writes.

## Handoff context

Pass resolved brain/source identities, changed canonical slugs and exact local
paths (especially actions), raw source references, event identities/versions,
source/calendar coverage and cutoffs, unresolved review records, and sync or
registration failures. Pass a previous same-day report if already available.
Never expose the private vault path in public artifacts.

Briefing loads the broader daily inventory; changed pages alone are insufficient.
It does not modify actions, register schedules, or save report pages unrequested.

## Batch and nested routing

The outermost user-visible ingest request owns one report. Specialized skills
return results to that owner; do not report per email, file, sample, or nested
invocation. A directly invoked specialized skill owns this handoff itself.
Later requests refresh the report, even on the same day, highlighting changes.
Unattended connector events do not independently push reports or create recurring
notifications. Existing authorized user-facing batch delivery may use this handoff.
